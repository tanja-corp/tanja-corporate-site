# TANJA オブジェクトマップ

サイトのオブジェクトが**どう紐づいているか**を見るための道具です。デザインデータ・概念図・ER図を**同じキャンバス**に載せ、上のメニューひとつで行き来できます。3つとも**同じ1つのデータ（`model.js`）**から描かれるので、どれかを直すと残りも同時に変わります。

## 開き方

`architecture/index.html` をブラウザ（Chrome推奨）で開くだけです。ビルド・インストール・外部通信はありません。

## 見方

| 操作 | 何が起きるか |
|---|---|
| 上のメニュー「デザインデータ／概念図／ER図」（キー 1・2・3） | **同じオブジェクトが**位置と姿を変えて動く。ページ上のカードが、ERでは1つのテーブルの行に合流する |
| オブジェクトをクリック | 選択。つながっているものだけが明るくなり、線の意味（動詞）が出る。ビューを切り替えても選択は残る |
| 右パネル「同じオブジェクトの3つの姿」 | そのオブジェクトが、デザイン・概念・ERでそれぞれ何者か（ページ上の位置、領域、テーブル）を並べて表示 |
| ダブルクリック | 同じオブジェクトを次のビューで見る |
| ドラッグ／ホイール／Ctrl+ホイール／「全体」（0） | 移動／スクロール／拡大縮小／全体表示 |
| 検索（/） | 名前・IDでオブジェクトを探して移動 |

- **デザインデータ**：実ページと同じ入れ子の骨格図。`slot 04`＝写真枠、`×4`＝繰り返し数、斜線＝仮置き。ナビ項目を選ぶと「移動先」の線が出る。デザイントークン（色・文字・余白）と使用箇所は右パネルの全体表示にある。
- **概念図**：領域（サイトの構造／会社と事業／写真・言語／出典と承認／人と採用）ごとに並べ、「〜する」の向きで結ぶ。
- **ER図**：CMSに載せるデータの形。PK・FK（斜体は自動生成）、必須、3言語、仮の値、多重度（縦2本＝1、鳥の足＝多、○＝任意）。丸いチップはそのテーブルの行。

## 1つのデータから3つが描かれる仕組み

`model.js` の中で、オブジェクト1つが最大3つの**面（facet）**を持ちます。ビューはこの面と `links` から毎回計算した結果で、**座標はどこにも保存しません**（配置は自動）。

```
オブジェクト  id / 名前（日・英）/ 状態 / 種類
  ├ design   ページ上の親・並び順・見た目の型・slot・htmlId・繰り返し数・使うトークン   → デザインデータ
  ├ concept  領域・領域内の順                                                        → 概念図
  └ er       テーブル（フィールド）または「あるテーブルの1行」                          → ER図
links        つながりの意味（動詞・多重度）                                            → 概念図の線 と ERの関係（＝外部キー）
```

面を持つ数だけ、そのビューに現れます。たとえば `coffee` はデザイン（作物カード）・概念図（コーヒー）・ER（`Crop` テーブルの1行）の3つに現れ、`header` はデザインだけ、`tanja` は概念図だけです。

**自動で決まるもの**（手で二重に書かない）

- ページ上の親子 → 概念図の「含む」線
- `design.slot` → ERの「`PhotoSlot` を使う」関係とフィールド
- `3言語` のフィールド → `Translation` へのつながり
- リンクの多重度 → ERの外部キー（`N:1` は「多」側、`1:N` は「多」側の表に `xxx_id` が付く）

## 「片方を直せば、もう片方が追従する」の例

| ここで直す | ここに出る |
|---|---|
| 名前を変える | デザインのカード・概念図のノード・ERのテーブル見出し |
| ERにフィールドを足す／「3言語」を付ける | ERの表、デザインカードの「3言語」バッジ |
| デザインの `slot` や繰り返し数を変える | ERの `PhotoSlot` への線と `×n`、写真枠の表示 |
| リンクを1本足す | 概念図に線、ERに関係と外部キー（例：`career_note_id`） |
| ページ上の親を変える | 概念図の「含む」線、ERの「ページ上の表示」 |
| ERの面を外す／オブジェクトを削除 | 行・つながり・参照が整理され、他のビューは壊れない |

これは `node architecture/test-core.js` が機械的に確かめています。

## 編集と保存

- 右パネルで、名前・状態・説明、デザイン設定、概念図の設定、ERのフィールド、リンクを直せます。「＋オブジェクトを追加」、「JSONを直接編集」もあります。
- **元に戻す／やり直す**（Ctrl+Z／Ctrl+Shift+Z）。入力中の連続した変更は1回分にまとまります。
- 編集は自動で**ブラウザ内の下書き**になります（黄色の帯）。`model.js` はまだ変わりません。
- **保存**（Ctrl+S）：Chrome／Edge では `model.js` を選ぶと**直接上書き**できます。それ以外は `model.js` をダウンロードするので `architecture/` に置き換えてください。保存後は Git でコミットします。

## 実サイトとのずれの検出

`model.js` は**実サイトを生成しません**（サイトの `index.html` は手で書いたもの）。その代わり、ずれを機械で検出します。

```
node architecture/check.js
```

`styles.css` のデザイントークンと幅のブレークポイント、`index.html` のセクションID・並び順・写真枠（`data-slot`）・プレースホルダー（`data-placeholder`）・繰り返し数（ナビ／言語／SNS／スタッフ／作物／プロジェクトの数）、`PHOTO_MANIFEST.md` の承認状態を照合し、違えば `ERROR` で終了します。サイトを変えたら、このコマンドで地図の直し忘れに気づけます。

```
node architecture/test-core.js
```

データ処理と配置の検査です（3つのビューが1つのモデルに追従すること、重なりや範囲外がないこと）。

## ファイル

| ファイル | 役割 |
|---|---|
| `model.js` | **唯一の出所**。オブジェクト・リンク・トークン・領域 |
| `model-core.js` | 派生（外部キー・つながり）、検証、編集の後始末（ブラウザ／Node共用） |
| `layout.js` | 3つのビューの自動配置と線の経路（座標は保存しない） |
| `skins.js` | 3つの姿の描画（SVG）。色は `model.js` のトークンから |
| `app.js` | キャンバス、カメラ、選択、履歴、保存 |
| `inspector.js` | 右パネル（編集） |
| `check.js`／`test-core.js` | 実サイトとのずれ検出／コアの検査 |

## 限界

- 配置は自動です。手で位置を動かして保存する機能はありません（ずれの原因になるため）。
- 図から `index.html` を生成することはしません。図を直したときは、実サイトも同じ意味に直し、`check.js` で照合してください。
- 実機の画面幅が狭いと、キャンバスは見づらくなります（PCでの利用を前提）。
